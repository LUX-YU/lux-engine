# H1–H6 — UE-like 先进渲染真实算法专项门禁

全部 H 阶段均为独立的**未来算法开发**，目前 NOT_IMPLEMENTED。先复核第 13/27 章和真实 Backend enabled caps，不预先建第二套 Renderer。

- H1 虚拟几何：Cluster HLOD、GPU Page Residency、feedback、HZB GPU Cull/LOD、Mesh/Indirect fallback；真实 Streaming/popping/VRAM oracle。
- H2 动态 GI 与 Reflections：SDF/Probe/Radiance/Screen trace、多 Pass denoise/temporal、可选 RayQuery/RT，软件合法 fallback；质量/延迟参考。
- H3 Temporal Super Resolution：History/motion/reprojection/reactive/shading rejection，cut/disocclusion/ghosting/flicker，动态尺寸和 GPU trace。
- H4 Virtual Shadow Maps：Atlas/PageTable/clipmap/feedback/dirty/cached pages、缺页 parent/fallback；真实 Shadow vs PCF/EVSM/CSM 参考。
- H5 Advanced Materials/Volumetric：BSDF/Volume shader/layout、3D Texture、光照与 Shader/Descriptor variant full ABI/DeviceCaps fallback。
- H6 Full 3DGS/Mixed：Gaussian GPU Chunk/Tile Bin/Sort/Splat/Alpha+Transmittance/Depth merge with Mesh；与参考渲染验证数值/视觉/复杂度。4D 动态 3DGS 是更晚的独立课题。

新增的 Native primitive 必须有真实 consumer/Shader/sync/quality reference，多个 Effect 仍使用唯一 Graph/Executor/DeviceSession；不需要 `RayRenderer/GaussianRenderer` 平行帧系统。按 workload W20–W25 每项单独 I/V、性能/质量/设备 fallback、Push STOP。


## 高级效果阶段的新先验条件

H1/H4/H6 除 Shader/算法本身外，必须证明第 31 章的 GPU page/chunk 大流量传输不会让 PROGRAM/CONTROL 饥饿、跨 GPU Queue family 的 ready/barrier 正确；H2/H3 的 GBuffer/LocalRead/History/Volume 需通过第 29/32 章真实编译/物理池/时间史证据；H5 在当前 `material::MaterialGraph`/ShaderIR/Toolchain 上扩展，而不是创建平行材质编辑器或把每个 BSDF 节点变成 RenderGraph pass。
