# D2：桌面内容编辑与持久化候选

本说明对应 v2 的 D2；不是 D2 已通过声明，也不启动 D3。基线为
`4aee84a48e235174534ca4a0fe0cc6afe39cfcd7`，分支为 `codex/editor-desktop-d2`。
最终源码身份和逐项结果见交付包 manifest 与 acceptance-results。

## 实现入口

- `app/main.cpp` 使用 lux-cxx 参数解析，选择已有项目，装配 provider，执行 `Editor::exec()`。
  无参数运行打开项目文件选择框；也支持 `--project <Project.luxproject>`。
- `core` 拥有 Project、文档注册／打开请求及安全点；不知道材质或 Flow 的业务分支。
- `documents` 中 SceneEditor、MaterialEditor、FlowForgeEditor 拥有各自内容、请求与 Editing 历史。
  资产读取／写入、模型导入、编译和链接使用 Process sender，最终结果通过预留的 Main 完成槽采用。
- `gui` 绑定真实 Pane、节点图及 typed Inspector。每个组件生成一个 CPP，编入 GUI target。
  `ui` 布局与底层领域 DLL 不编入 Inspector 业务绘制代码。
- Renderer／RenderView 继续拥有渲染与图像生命周期；CPU 引用和真实 GPU 完成水位同时约束退役。

## 场景编辑

`setField`／预览 token／局部 Undo 使用同一个 SceneEditor。字段值的普通失败不修改作者内容或历史。
`createObject` 按 World 声明提供空对象、2D 或 3D；`reparent` 仅在声明 Parent schema 时可用，并保留局部变换。
Outliner 提供创建、删除、子树删除、拖动修改父级与脱离父级。环形关系和仍被引用的删除明确拒绝。

对象历史保存作者组件 codec 的不可变捕获。恢复先在私有 Registry 解码，使用 EnTT 的空闲身份提示解析最终 Entity 引用；
成功后提交到真实 Registry。所有对象身份先建立，再转移准备好的组件。删除回调仍能看到原组件和原持久身份。
公开通知发生在内容／历史提交后。临时 Registry 仅属于本次准备，不是第二份可写 World。

模型放置复用这套对象历史。模型读取、CPU 解码、Main 接纳、过期捕获重试与关闭排空均由文档拥有。
有 Parent 的 World 保留模型层级；无 Parent 的 World 合成局部变换，不自动引入层级。
皮肤／动画变形、无法由 TRS 表示的合成结果、错误分区和缺失依赖明确拒绝。

冻结保存保留原 Scene／Simulation 描述、分区身份、未知原始 payload，排除运行时派生状态。
保存 S1 期间编辑 S2，成功只把 S1 标成已保存。同一捕获和票据可重试；文件效果与清单发布分别记账。

## 验证入口

`cmake/installed-consumers/editor-d2` 是独立安装消费者。仅以安装包 targets 编译：

- 外部 domain DLL 的真实反射组件及 codec。
- 外部 GUI DLL 的一组件一 CPP、嵌套容器 Inspector。
- `protocol` 中的 Scene／Material／Flow／Process／发布／导入测试及 CTest 驱动。

只用 RelWithDebInfo。配置时提供现有依赖前缀、Python、clang-format 与 `D2_FLOW_LINKER`；
运行时提供当前 SDK、外部基础依赖的 DLL 路径。先完成 `--target all -j 4 -- -k 0`，构建失败不执行旧程序。
测试显式启用断言，并要求实际退出码及完成记录；故意中断的发布测试只接受约定的 exit 86，随后由另一进程验证恢复。
`protocol/Seed.luxpak` 是 D1/D2 开发验证沿用的固定输入；fixture 通过正式 DLL codec 编码作者内容。
消费者中的一次解码拒绝只在测试 DLL 内，未装入正式 SDK。

这些测试会实际创建窗口／UI／Renderer 并调用业务入口，但程序驱动的绘制不证明真实鼠标拖放或桌面关闭交互通过。

## 保留的限制与待验收项

- 桌面工具曾返回失效 screenshotId／缺失输入几何。真实资产拖放、节点手势、保存期间取消关闭仍需人工桌面验收。
  旧 IME、鼠标捕获或 q7/q8 结果不能替当前二进制背书。
- 需要重建持久空间索引的保存返回 `INDEX_REBUILD_REQUIRED`；没有删除索引来伪造成功。
- 未知组件可能持有引用。删除原始对象时缺少相关 provider 会拒绝；不会猜测或丢弃未知数据。
- 当前只向既有分区放置对象；没有新增分区／重新分区产品能力。
- 导入支持已验证的静态模型及源依赖闭包；歧义源名称需要明确关联，不静默重绑身份。
- Flow 的 native metadata 来自冷装配；没有注册的 ability／event 不显示为可用业务。没有扩展新的插件发现平台。
- 多文件中断验证覆盖已执行的边界；不能把一次 PREPARED 中断当成所有发布边界已验证。

## 人工桌面验收

1. 打开候选 SDK 的 Editor 和已有项目，选择 Mesh，拖动一项 Transform 后 Undo／Redo；确认一次拖动只有一条历史。
2. 浏览项目资产，将同类型资产替换 Inspector 引用；把导入的静态模型拖进 Scene，检查放置、层级和撤销。
3. 在 Outliner 创建对象，拖动修改父级；尝试制造环及删除仍被引用的父对象，确认错误保留原内容。
4. 打开材质和 Flow 文档，编辑、编译并分别撤销，确认另一文档内容和游标不动。
5. 保存时继续编辑，取消一次关闭，再次保存；正常退出后用新进程重开检查内容。

记录候选身份、项目输入、实际字符／画面、错误与正常退出结果；没有结果的项保持未验证。
