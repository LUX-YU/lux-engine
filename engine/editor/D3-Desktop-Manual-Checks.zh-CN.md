## 持续按住鼠标时取消

1. 在测试项目打开 Main 场景，选中 Object 1；记录 Transform 的 X 原值与文档保存状态。
2. 按住 X 数值控件开始拖动，确认数值已经变化；保持鼠标左键按下。
3. 在仍按住左键时按 Escape，再松开鼠标。必须恢复原值，不能新增内容历史。
4. 再做一次拖动并正常松开。应仅提交一次；一次场景 Undo 恢复原值，Redo 恢复新值。
5. 同时打开有独立历史的 Material，确认场景取消/Undo 不改变材质内容。

记录屏幕操作顺序、前后值、Undo/Redo 结果及所用 EXE/DLL 哈希。仅看取消按钮返回成功、拖完后再按 Escape，均不覆盖第 3 步。

## 裁剪时的持续手势

先把 Inspector 的可见高度调整到需要滚动的范围。开始拖动一个数值，保持左键按下，用滚轮让该控件离开可见范围，然后松开；回到原控件核对。

本候选既有策略是：控件离开本帧实际绘制范围时，已有手势在正常推进点提交；整个 Inspector 因折叠/零布局失去显示事实时，也在 owner 推进点收尾。每次手势最多一条历史，不能留下活动 token 或在重新出现时重复提交。提交被 BUSY 拒绝时保留 token，解除后重试同一手势。Renderer 背压导致没有新 UI 帧时，不应自行结束手势。

其中 BUSY、零布局、折叠、未调用 draw、容器定位失效等已有接口/事件注入回归；这份人工清单补的是实际持续输入。工具当前的 `drag` 把按下、移动、松开合成一次调用，没有独立的持续按下接口，因此尚不能准确执行上述组合。
