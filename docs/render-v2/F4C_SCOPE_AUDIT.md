## Minimal additional native scope proposal (not implemented)

If the user elects to close these native gaps in F4-C, limit additions to the existing mechanisms:

- Image dimension/depth/cube flags and ImageView validation in `memory/Memory.hpp`, `memory/Memory.cpp`;
  dimensional copy regions in existing `graph/Copy.cpp` and extent/budget/alias checks in `graph/Resources.cpp`.
- Explicit cold target extent input in `graph/Executable.hpp`; resolution in existing native compilation only,
  without a Target owner, registry or Runtime. Shape changes participate in the existing native identity.
- Native descriptor dimension validation in `shader/Bindings.cpp` and existing view recipes in `graph/Recipes.cpp`.
- Vertex/index/indirect record values in existing `graph/Executable.hpp`, checks in `Recipes.cpp`, commands in
  `Record.cpp`, preserving declared Graph VERTEX/INDEX/INDIRECT access evidence. No Feature or Mesh owner.
- Actual generated 3D/Cube sampling and vertex/index/indirect readback fixtures under `test/NativeGraph*`
  plus bootstrap wiring. All existing tests and F3/R4 ownership/performance regressions remain required.

F2, Core, Transport, generator and Description remain read-only. A concrete conflict in those layers stops
the affected extension with the smallest failing fixture; it does not authorize a substitute metadata system.

No additional implementation has been made under this proposal. C1/C2 fixes, C3 lifetime tests and P1 performance
investigation can proceed independently. Full F4 closure cannot silently erase the unresolved scope decision.

## Future boundaries retained

F5 must settle public Feature API dependency direction with the F6 implementation, and separate native shared
backing mechanism tests from F7's real DataSet/publication chain. Plugin generation is a build/load contract,
not per-frame parsing. None of these future decisions authorizes production DataSchema, TypedStorage,
Feature SDK, Scene or Runtime here.

## User decision: bounded native draw extension (approved before implementation)

The user authorizes only vertex binding, UINT16/UINT32 index binding, direct indexed draw,
ordinary indirect draw and indexed indirect draw. Commands reference existing Graph ResourceUse
indices; they do not introduce a second resource identity list. Existing Graph ranges, Sync2,
RAII and slot retirement remain authoritative. GPU-generated arguments are consumed directly.
One indirect command per native recipe is sufficient; MultiDraw scheduling, IndirectCount and
Mesh Shader are outside this authorization. GPU-generated command contents must satisfy Vulkan
index/vertex bounds and firstInstance=0; CPU admission validates the declared storage and command
parameters, not GPU-generated bytes by CPU readback.

Before this extension, C1/C2 actual baseline failures, C3 normal no-failure result, five fixed GPU
tests and P1 controlled original/finalized-link comparisons are retained under F4-C/pre-draw,
baseline-reproduction, performance-pre, relink-control and development. Final qualification is pending.
