# ADR 2026-08-22: 唯一行为图与 modules → ecs → engine 边界

Status: accepted; supersedes Contribution/Pack and Extension ABI v4 decisions  
Baseline: `03d369f5a628a80916c463a51d2bb5ae2335bc58`

## Decision

`modules/` owns ECS-free mechanisms, `ecs/` owns every Entity/Component-aware
domain and System, and `engine/` owns products and orchestration. `ISystem +
Schedule` is the only World behavior graph. Renderer `FeatureCatalog` is the
only renderer capability graph.

Delete `SceneFeature`, `SceneContribution`, `WorldSceneFeature`, Runtime
`RenderEffect` and Runtime Pack identity. Built-in composition is direct code;
shipping composition is generated code, never a Runtime registry.

Extension ABI v5 is a same-toolchain hard break. It exposes a descriptor and
narrow direct callbacks, with System installation allowed only before Schedule
freeze. Module metadata is validated as one load batch and then committed to
the separate Reflection and Component registries. Module lifetime remains a
real `ModuleLease` concern.

SceneDescription v3 and WorldSource v5 are direct format breaks. Authoring does
not store runtime requirements. SceneDescription stores Component/Extension
loading facts but never renderer requirements; renderer capability roots come
only from product-installed render behavior, pipeline-intrinsic RenderProfile
roots and FeatureDescriptor dependencies. Unsupported older versions are
rejected.

Published Scene topology is immutable. Loading an Extension makes its code and
metadata available to the next Scene creation/reload; it never adds a System,
RenderStage or RenderFeature to an already published Scene. Unload is rejected
or deferred while a Scene retains the ModuleLease.

SceneRuntime is the only Scene owner and directly owns SceneDescription,
World, SceneServices and Schedule. SceneServices owns the SceneRenderBinding
shared by render-facing Systems. RenderSystem borrows that binding, owns the
RenderSceneLease, and participates in the ordinary ISystem close protocol.
Schedule close guarantees reverse-topology completion, not merely reverse
request order: render-facing consumers are quiescent before RenderSystem starts
closing the remote Scene.

The rendered-Scene cold transaction has two distinct failure guarantees. The
local `FeatureCatalog` closure/preflight completes before any renderer command,
so a local failure performs zero remote operations. Once remote assembly has
started, failure closes the candidate `RenderSceneLease` immediately; remote
operations may have occurred, but no remote Scene leaks and neither Schedule
nor World is published. `SceneRenderBinding` is sealed only after successful
assembly and has no published-topology mutation API.

## Implemented RenderStage classification

| Classification | Implementations | Reason |
|---|---|---|
| pure Stage | Camera2D/Camera3D upload, Grid2D/Grid3D feature parameters, HeightFog, Skybox, SpatialCull, DebugLine | lifetime equals RenderSystem; projection/cache only |
| ordinary render-facing `ISystem` | Image2D, mesh/skinned mesh instances, directional/point/spot lights, Water | owns independent observation/request/resource retirement |
| ordinary render-facing `ISystem` | CameraView, ClassicMeshBatch, TerrainTile, PixelField2D, Tilemap2D | owns readiness, asynchronous preparation, publication or independent close |
| ordinary provider `ISystem` | Residency | independent admission, ticket completion and quiescence |

Concrete render-facing Systems expose a static `requiredRenderFeatures()`
declaration. The cold product recipe reads it in the same block that adds the
System and appends the result to a local root vector. The generic `ISystem`
interface remains renderer-blind.

## Consequences

- Engine Runtime contains no domain `ISystem` or public Component.
- Runtime spatial2d/spatial3d/animation/physics/navigation parallel domains
  disappear after their behavior moves into ECS.
- Render extraction uses one RenderSystem with a private immutable stage list.
  A Stage is eligible only when its lifetime exactly equals RenderSystem, it
  has no independent async admission/ticket/lease/readiness/close, it never
  writes ECS, and it only projects ECS state to render commands. A Stage may
  own an observer or dirty cache whose lifetime is exactly its own. Independent
  behavior lifecycle belongs to an ordinary System.
- Render-facing Systems declare renderer requirements on their concrete types;
  direct cold composition appends those declarations to a local vector while
  adding the System. ISystem has no renderer API and there is no runtime
  requirement registry.
- Renderer preflight is side-effect free. Unknown roots, missing dependencies,
  cycles or missing attach configuration fail before any remote operation.
  Remote assembly failures roll back through RenderSceneLease and leave no
  leaked remote state or published World.
- FogFeature owns authoritative fog state. HeightFog extraction knows only
  FogFeature; WaterFeature optionally consumes that renderer-side state and
  uses the no-fog default when Fog is absent. No AtmosphereFeature is added.
- Renderer resource owners and pass producers both use `RenderFeature`; the
  former inherit an empty `addPasses`. The former Renderer-only base split and
  its parallel set identity are deleted, leaving FeatureCatalog as the sole
  capability graph.
- The former `engine/spatial3d/SceneCatalog` is split by field owner. Cooked
  cell/LOD/section/L3SC contracts live under `ecs/scene_format/spatial3d`;
  residency capacity and demand-channel policy live under
  `ecs/spatial3d/streaming`.
- `engine/scene` and `engine/extensions/api` remain thin shared contracts.
- EntitySceneCatalog and EntitySectionRecordStore have no successor objects.
  SceneRuntime moves SceneDescription into its final member before constructing
  any System that borrows SectionRecord storage, which is immutable thereafter.
- ReflectionRegistry and ComponentTypeCatalog remain separate query surfaces,
  but a module load has one generated pending draft and one validate-before-
  publish event. Generated registration plumbing is not a public metadata
  object model.
- Domain IDs retain semantic ownership. ExtensionId remains an Extension
  contract, Authoring IDs remain Authoring contracts, and WorldActorId remains
  distinct from PersistentEntityId. One-way representation conversion is a
  legitimate adapter; long-lived synchronization of two truths is not.
- Editor panels register directly with UISystem on the main thread. The
  editor owner binds a provider ModuleLease; no panel catalog/host/ticket
  lifecycle exists.
- Cook emits a build-only project-usage manifest and direct generated game
  composition source. These end at the build graph; Runtime reads only cooked
  pak, LaunchManifest and the deployed Extension list. Physics2D is never
  added to the base Player's static composition.
- Compatibility headers, type aliases, v4 symbols and old target aliases are
  not retained.

## Superseded material

Any earlier v2 document that prescribes Contribution hosts, Runtime Packs,
Runtime-owned spatial Systems or ABI v4 registration is historical context,
not an implementation requirement. This ADR and
`.internal/directory-target-product-architecture.md` take precedence.
