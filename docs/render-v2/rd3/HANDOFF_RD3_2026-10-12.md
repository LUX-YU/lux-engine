## 本次确定的目标方向

- 整个源 ZIP 的 21 个章节和所有阶段工作单均以新的 RenderEffect/Graph/Context/ResourceDomain 模型重写，旧 Scope DataSet 必需 CPU mirror/Scene owns Feature+Graph 不再是目标架构。
- `RenderRuntime` Client 对 Transport/协议负责；`RenderBackend` Server owns Scene（Scene owns View）、独立 Target、RenderEffect/Native Graph cache、ResourceDomain、唯一 Frame loop；具体 Vulkan 只在 `backend/vulkan`。
- View 公开选择 `RenderEffectId`，Backend 将 Effect revision/Target signature/Device caps 编译与绑定成 `RenderGraphId`。同一个 Graph 可由不同 Scene 的 View 共享，不能共享不相容的 Scene/History GPU 状态。
- Effect 持 Feature 的可编辑配置，Feature 无状态优先（普通 C++20 build/共享算法），Graph 不保留 `[this]`/Native callback 形式的借用。Effect 编辑是所有消费者安全点原子候选更新；Exposure/Light value 等 Hot 数据不重编译。
- GraphIR 是中立 IR；Native Compiler C9–C13 生成不可变 `vulkan::Graph`，`vulkan::Executor` 借 `GraphExecutionContext`（per execution config/FIF slots、Descriptor、scratch、tickets）执行。
- 一次 `execute(graph, view, target)` 生成该 Target 的完整最终画面；Graph 内 GBuffer/HDR/Shadow/Composite 临时资源均由声明和 Compiler 管理。多个 View 一 Target 需用同一 Graph 显式多 View inputs/Composite Pass；外部 Offscreen Target 的**最终**画面仅显式导入才可消费。
- `ResourceDomain` 是 Backend-managed 层级所有权容器，`ResourceRegistry` 唯一 type lookup，子域只读祖先；GPU backing 对上层仅资源句柄，真实 Native LastUse 决定物理回收；Engine ECS/Assets 保持 CPU 数据权威，不建第二 CPU ECS。
