# Lux Architecture Normative Execution Contract for Coding Agents

Status: **Normative — MUST / MUST NOT / STOP (v3)**

本文不是设计讨论，而是实现约束。若与本 docset 其他“建议/示例”措辞冲突，以本文为准；若与 repository canonical L0–L4/L5 architecture 真源冲突，必须 STOP 并重新 review，而不是自行折中。

---

## 1. Global Rules

### MUST

- MUST 读取当前 HEAD 后再修改。
- MUST preserve L0–L5 dependency direction and keep Product/Application composition outside architecture layer numbering。
- MUST hard-cut migration；删除旧路径时不保留 shim/alias/forwarding compatibility layer。
- MUST 使用 existing Sender/Receiver vocabulary；不得并行发明第二套 async framework。
- MUST 将 UI known-type hot path 保持 generated/typed。
- MUST 让 window lifetime 与 tool/task/resource lifetime 分离。
- MUST make qualification evidence reproducible from the exact committed source snapshot it names。
- MUST keep Dear ImGui/imgui-node-editor private to the approved Lux UI backend after Wave U migration。

### MUST NOT

```text
EditorContext singleton
AssetVfs::Get() / lazy AssetVfs singleton / static hidden VFS state
ExecutionRuntime singleton
RenderRuntime singleton
ServiceRegistry / EditorServices
JobSystem / JobManager
CompilerManager
GenericCompiler
GenericGraphIR / UniversalGraph
runtime-reflection Inspector fallback
AssetIndex in Wave D
SelectionRegistry in v1
Graph payload property bag
engine/authoring resurrection
retained-mode WidgetManager / persistent visual tree
IUiBackend leaf-virtual abstraction before a second real backend/approved need
```

## 2. Source / Qualification Reproducibility Contract

A qualification report MUST correspond to a self-contained committed source snapshot.

MUST record：

```text
git rev-parse HEAD
git status --porcelain    # empty for qualification source
git diff --exit-code
```

Every source named by configured build/test targets MUST be tracked or generated by a committed/reproducible rule.

If CMake/build metadata references a local/untracked source used by the evidence, qualification is invalid for that HEAD until the source/rule is committed and the matrix is rerun from a clean checkout.

MUST NOT delete a test target merely to make a missing-source qualification failure disappear unless coverage removal is itself explicitly reviewed.

## 3. Exact v3 Ownership

```text
EditorApplication MUST own:
    ExecutionRuntime
    root TaskScope
    mutable AssetVfs
    production/editor AssetRead endpoint/port
    Toolset
    EditorSelection
    UISession
    SceneMetaManager
    RenderRuntime/platform state when configured

EditorContext MUST own no product/application service lifetime.
EditorContext MUST carry/reference:
    Toolset&
    AssetVfsView
    AssetReadPort
    ExecutionRuntime&
    TaskScope&
    EditorSelection&
    UISession&
    const SceneMetaManager&
```

No alternative ownership tree is permitted without architecture review。

`EditorApplication` is an L5 application/composition leaf and may directly produce the Editor executable。MUST NOT introduce a separate Product/Application composition layer merely to own these objects。

---

## 4. EditorContext Contract

MUST expose typed named capabilities only：

```text
toolchain()
vfs()              # AssetVfsView, no mount mutation
assetRead()        # copyable AssetReadPort/capability
execution()
tasks()
selection()
ui()
sceneMeta()
```

MUST NOT expose：

```text
get<T>()
resolve(string)
services()
registry()
anything()
```

Exception：`Toolset` itself MAY expose typed `get<T>/find<T>` because its semantic domain is explicitly “L4 tool capability set”。

`vfs()` MUST return/read an `AssetVfsView`, not mutable `AssetVfs&`.

---

## 5. Toolset / EditorApplication Tool Lifecycle Contract

Toolset MUST support：

```text
install<T>() during composition
get<T>() required lookup
find<T>() optional lookup
freeze()
```

MUST use typed stable identity；MUST NOT use string keys。

Missing required `get<T>()` MUST fail closed；MUST NOT auto-create/no-op fallback。

After `freeze()`：

```text
NO install
NO remove
NO replace
```

If `EditorApplication` exposes `installTool<T>()`, it MUST respect application state：

```text
COMPOSING  -> install allowed
RUNNING    -> explicit FROZEN/invalid-phase failure
STOPPING   -> explicit STOPPING/invalid-state failure
JOINED     -> explicit STOPPING/invalid-state failure
```

STOPPING/JOINED MUST NOT dereference an already-reset/disengaged Toolset owner.

## 6. Lux UI / Backend Isolation Contract

`modules/function/ui` is the public UI owner.

After the corresponding Wave U migration, Editor/generated/plugin public or feature code MUST NOT include/expose：

```text
imgui.h
imgui_internal.h
imgui-node-editor headers
ImGuiContext / ImGuiIO / ImGuiStyle / ImGuiID
ImVec2 / ImVec4
ImTextureID
ImGui*Flags
ImDrawList
imgui-node-editor types
```

MUST use Lux-owned semantic types/API (`ui::Frame`, scopes, Theme, `ui::TextureHandle`, `ViewportElement`, `NodeCanvas`, etc. or approved exact equivalents).

MUST preserve the immediate-mode execution model at leaf controls while allowing object-oriented long-lived semantic objects such as `Pane`/`UISession`.

MUST NOT build a retained-mode persistent widget tree merely to wrap ImGui.

MUST NOT create a generic `IUiBackend` virtual leaf interface before a second real backend/approved requirement proves the need.

Legacy MAY be used as selected visual/interaction/behavior reference；MUST NOT copy Legacy ownership/manager/raw-ImGui architecture for parity.

## 7. AssetVfs / Asset Loading Contract

MUST preserve `AssetVfs` as an explicit instance with explicit initialization and shutdown。

MUST split semantics：

```text
AssetVfs       = mutable low-frequency mount/unmount control plane
AssetVfsView   = read capability for resolve/open/enumerate/pathOf
AssetReadPort  = asynchronous/time-spanning read capability used by asset_loading
```

Concurrent read vs mount publication MUST have an explicit race-free contract；current preferred/implemented direction is immutable MountTable snapshot publication with provider lifetime retained by snapshots。

Script/runtime code MUST NOT receive mutable AssetVfs control plane and MUST NOT perform synchronous potentially-blocking VFS open on game/main thread。Editor frame/UI hot path MUST also use `AssetReadPort` for content reads that may touch storage；`AssetVfsView` is primarily path/mount visibility/query capability。

Current `process/asset_loading::loadAsset<T>()` MUST remain the typed async decode workflow；product composition MUST provide a non-owner-thread-blocking production `AssetReadPort` endpoint before exposing async asset loading to scripts。

## 8. Compiler Contract

Every Compiler installed in Toolset MUST be logically stateless and reentrant。

### Compiler MAY own

```text
immutable environment
immutable toolchain/search config
copyable L2 scheduler capability
shared_ptr<const Config>
```

### Compiler MUST NOT own

```text
current graph/source
current IR
current diagnostics
current temp path
current result
in-flight job list
stop source for individual jobs
bool compiling
whole-compiler mutex serializing compile calls
```

The following MUST be legal with overlapping execution：

```text
sameCompiler.compile(A)
sameCompiler.compile(B)
sameCompiler.compile(C)
```

---

## 9. Async Source Ownership

Asynchronous compile/import/cook MUST consume an owned request/snapshot。

Allowed：

```cpp
compiler.compile(graph.clone(), options);
```

Forbidden：

```cpp
compiler.compileAsync(graph); // operation stores pointer/reference to mutable document source
```

Sender/operation state MUST own source for the duration of work。

## 10. Sender State Contract

Per-invocation mutable state MUST live in Sender operation state or objects exclusively owned by it：

```text
source snapshot
request options
stop callback/token
IR/context
temporary files/directories
diagnostics being built
receiver
result under construction
```

Compiler object MUST remain unchanged by normal invocation execution。

## 11. Synchronous Core Contract

Domain async Sender MUST delegate to the same canonical synchronous semantic core used by CLI/tests/cooker。

MUST NOT create a second async-only lowering/compiler implementation。

Material example：

```text
compileMaterial() = sole semantic compile core
MaterialGraphCompiler::compile() = scheduling wrapper
```

FlowForge equivalent。

## 12. L2 Wave B Scope / V2 Extension Contract

The foundation execution vocabulary is：

```text
ExecutionRuntime
CpuScheduler
MainScheduler
TaskScope
TimerQueue/TimerSender
PortSender
```

Wave B itself MUST NOT have introduced：

```text
BlockingScheduler
ProcessSender
file service framework
dynamic operation bundle
endpoint registry
JobSystem
business/domain operation registry
```

Wave V2 is the approved later gate that MAY/MUST provide `BlockingScheduler` or equivalent native async IO when synchronous storage requires owner-thread isolation.

If BlockingScheduler exists from V2, later Toolchain/runtime blocking stages MUST reuse it；MUST NOT create feature-private blocking pools.

`ProcessSender` remains a separate P1 capability and MUST NOT be introduced without a real subprocess lifecycle requirement and explicit approval.

## 13. ExecutionRuntime Contract

Runtime MUST own CPU worker backend and bounded queues。

Runtime MUST provide/semantically support：

```text
cpu()
main()
timer()
drainMain()
requestStop()
join()
```

Runtime behavior must enforce：

```text
ACTIVE -> STOPPING -> JOINED
```

After STOPPING, new admission MUST fail closed。

Successful join MUST imply no runtime-owned active worker/operation remains。

---

## 14. CpuScheduler Contract

MUST：

- satisfy project-selected stdexec scheduler expectations；
- be copyable lightweight capability；
- schedule onto Runtime-owned workers；
- support real parallel execution；
- bounded admission；
- reject after runtime stop。

MUST NOT：

- own independent worker pool per copy；
- know domain payload；
- serialize all work behind one global mutex。

---

## 15. MainScheduler Contract

MUST enqueue continuation to Runtime-owned bounded main mailbox。

Continuation MUST execute only via application owner `drainMain()` on owner thread。

MUST NOT create a second main thread。

Worker completion MUST NOT directly mutate UI/Editor thread-affine state。

---

## 16. TaskScope Contract

TaskScope is P0, not optional。

MUST：

- own operation state until terminal completion；
- provide stop propagation；
- reject start after stopping；
- provide a close/await path；
- guarantee no detached owned task after successful close；
- account for admitted-but-not-yet-registered starts；
- be safe when eager Sender start/completion re-enters the same scope。

v3 `EditorApplication` MUST own one root TaskScope；`EditorContext` MUST only reference it。

Window destruction MUST NOT stop root scope。

No project/document sub-scope framework may be introduced until their lifetime contract is separately approved。

### 16.1 Re-entrant synchronization rule

TaskScope MUST NOT hold its own admission/state mutex while：

```text
calling eager async_scope::spawn / Sender start
executing user Sender code
executing completion callbacks
invoking a stop path that can synchronously invoke callbacks
```

A correct implementation MUST reserve/admit the start under lock, release lock before eager start, then resolve/decrement the reservation on every success/failure path。If requestStop/close races after the admission decision, that already-admitted start MAY finish registration but MUST become part of the stopped scope and MUST NOT escape ownership。`close()` MUST set STOPPING before waiting and MUST not become CLOSED until：

```text
starting/admission reservation count == 0
AND
owned async operation count == 0
```

Simply unlocking before spawn without a reservation is forbidden because close could observe empty too early.

---

## 17. Cancellation Contract

MUST use stdexec stop token/source/callback vocabulary。

MUST NOT add independent cancellation framework。

Compiler API MUST NOT expose ambiguous `cancel()` for all jobs。

Cancellation is cooperative；third-party blocking call need not be forcibly killed in v1。

---

## 18. Domain Result vs Execution Failure

Compilation semantic failure MUST remain domain result：

```text
invalid graph
type mismatch
lowering error
shader compile diagnostic
link failure as FlowForge domain/tool failure
```

Execution framework failure/rejection MUST remain execution concern。

MUST NOT merge both into one undifferentiated `EAsyncError`。

TaskScope is lifetime ownership；callers MUST observe/materialize domain/execution outcomes before handing a terminally-unobserved operation to a lifetime-only scope path if the chosen implementation otherwise discards them.

---

## 19. Compiler Environment Contract

Installation/toolchain configuration MUST be immutable environment, not invocation mutable state。

Material environment MUST be able to carry relocatable shader include roots/target config；MUST NOT rely on original build/source absolute paths baked into installed library。

FlowForge environment SHOULD carry linker/target/toolchain paths；invocation options carry module-specific semantic input。

---

## 20. Asset Wave D Contract

Wave D MUST consume VFS directly through `AssetVfsView`.

MUST NOT create AssetIndex/Catalog framework。

File switch correctness MUST use generation filtering。

MUST NOT add `clearPending()` as substitute correctness mechanism。

Background import/cook MUST use Toolset + EditorApplication-owned root TaskScope + L2/V2；NO window-owned threads。

AssetBrowser UI MUST use Lux UI public API；drag payload and thumbnail/public image handles MUST not expose backend pointers/`ImTextureID`.

---

## 21. Selection Contract

v1 MUST have exactly one EditorApplication-owned、EditorContext-referenced `EditorSelection` for one active Scene editing target。

Entity selection identity MUST be `EditorSceneHandle + Entity`。`EditorSceneHandle` MUST be an L5 generational live-instance handle。

MUST NOT use Scene AssetId as live Scene identity。MUST NOT introduce L3 `SceneId` solely for Editor selection。Reload/destroy MUST invalidate old scene-handle generation and clear stale selection。

SceneOutliner/Viewport write it；Inspector observes it。

MUST NOT introduce SelectionManager/SelectionRegistry/per-pane competing selections。

---

## 22. Generated Inspector Contract

Known first-party/plugin component UI MUST be generated typed C++.

Generated code MUST call Lux UI public `EditorValueBinding<T>`/approved typed UI surface and MUST NOT include Dear ImGui.

No runtime-reflection fallback for normal editing.

Plain fields may direct-write + `registry.patch<T>()`; semantic fields such as Parent MUST use canonical domain mutation (`reparent/detach`) or be readonly/hidden.

Undo must preserve live editing while recording one operation per completed gesture; backend-specific item-state APIs MUST NOT be required in EntityInspector code.

## 25. Persistence Stop Gates

MaterialEditor durable open/save MUST STOP if active MaterialGraph source codec/document identity is not approved。

FlowForgeEditor durable open/save/packaging MUST STOP if FlowGraph codec or stable ScriptSymbol source identity is not approved。

In-memory edit/compile integration MAY proceed after its other gates, but MUST NOT invent persistence or claim durable completion.

MUST NOT solve these gates by restoring legacy Authoring。

## 26. Product Target Contract

Final shipped game MUST be modeled as a project-specific generated executable target。`PLAYER` MAY remain as a runtime-clean qualification profile only；MUST NOT become the normative final-product executable architecture。

Coding agent MUST STOP before implementing target generation if project manifest / target input contract is not approved；MUST NOT invent a generic Player/Host framework or manifest format。

## 27. Async Script / Cross-frame Operation Contract

MUST distinguish：

```text
Sender/domain async operation = external time-spanning work
script continuation           = language/runtime suspension state
```

Before implementation, the script continuation contract MUST explicitly freeze at least：

```text
script instance identity/generation
continuation/program point
locals/value state across suspension
resume result/error channel
cancellation/scene shutdown
resume queue/stable point
nested/repeated async behavior
ordering/reentrancy
```

Delay MUST use Timer semantics；asset loading MUST use AssetReadPort/typed AssetLoad Sender；GPU/physics queries MUST be domain-owned async operations。

Script invocation MUST return control to Simulation when suspended。MUST NOT：

```text
sleep game thread
sync_wait asynchronous Sender on game/main thread
Wait GPU fence/readback on normal gameplay path
retain native stack frame across frames
resume script directly from arbitrary worker/render callback
```

Completion MUST enqueue a stable resume record and continue at an explicit Simulation/script resume point。Scene/script shutdown MUST invalidate/cancel continuations safely。

## 28. Architecture Change Stop Conditions

STOP immediately if implementation appears to require：

```text
new upward dependency
new global Manager/Services/Registry
change of EditorApplication/EditorContext ownership
change of Toolset semantics
shared graph owner move
payload representation rewrite during UI/topology work
new source file format/document identity
new project manifest/target input format
script continuation ABI invented by coding agent
compatibility shim for retired architecture
Dear ImGui/public backend type outside private Lux UI backend
retained-mode widget framework
IUiBackend abstraction without a second real backend/approved need
```

The agent must report the blocking fact and smallest missing design decision, not invent missing architecture。

## 29. Test Obligations

Every new/fixed P0 execution primitive MUST have：

```text
success
capacity exhaustion
stop before start
stop during queue/race
runtime shutdown race
owner-thread validation
parallel stress
no detached state after close/join
```

TaskScope specifically MUST have：

```text
synchronous eager callback -> requestStop re-entry
synchronous eager callback -> nested start re-entry
start vs close race
start vs stop race
close waits admitted starter reservation
no user/stop callback under TaskScope state mutex
```

Every Compiler async integration MUST have：

```text
one compiler instance, N parallel invocations
source mutation after snapshot does not affect in-flight compile
stale revision discard
window destruction survival
application shutdown cancellation/close
```

Every UI migration MUST have：

```text
Lux UI public headers compile without ImGui include paths
migrated Editor target compiles without direct ImGui/node-editor headers
generated/plugin binding compiles without ImGui dependency
only approved private UI backend links backend libraries
```

Every architecture migration MUST run relevant product closure and install/relocated consumer tests from a reproducible committed source snapshot。
