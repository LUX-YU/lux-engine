## 2. 目标架构简版

Scene owns Views；View 不知道 RenderEffect/RenderGraph/Target。RenderEffect 持 RenderFeatures + one editable logical RenderGraph，不持 Scene/View；RenderBackend 持 EffectId→(SceneId,ViewId,TargetId) 的**唯一可编辑** Attachment 关系，Target 只有 neutral desc/layer 规则。Compiler 用 Feature/DataSchema/PassSchema/Graph Use 生成 GraphIR+ResourcePlan；attach 才 acquire/cold-create GPU scoped storages，成功后由 Backend move-only Attachment 持 ResourceLease；GPU backing 位于单 DeviceSession ScopedResources，ResourceScope：Global/Scene/View/Attachment-private/Graph transient。Compiler 冷态决定 Slot，Executor 热态直接使用 PreparedBindings，不再查 Domain/Type，跨多 Scene/View 共享 immutable shader/PSO code，native transient/histories分开。

Vulkan: Native bootstrap owns InstanceContext；它的稳定地址和生命周期必须先于、长于唯一 DeviceSession。DeviceSession owns DeviceContext (VkDevice/VMA/Queues/caps), ResourceContext (Pools/Staging/Transfer), Native resource storages, compiled Native Graph, GraphExecutionContext, Target native backing and retirement。`RenderBackend` neutral，只通过 Native Provider seam 对接；Engine/ECS/Editor/Plugins 仅依赖 `RenderRuntime` neutral R2 PROGRAM/CONTROL/UPLOAD/Reply。未来 D3D12 是另一 native implementation，不要求修改 Engine 的 `GridProjection`/`MeshProjection`。

ECS 数据桥：插件可注册 DataProjection (Component observer/change-set, typed conversion to neutral DataSchema, prepare/commit/discard under backpressure, CodePin)。RenderSystem 不内建每 Feature 的 Proxy/switch；Grid 可来自 ECS 或 Editor 直接 Producer；Mesh、Light、Gaussian 可来自 Engine/Plugin/External source。CPU World/Asset remains authority，Native GPU storage 是对应状态快照或 GPU-owned data。

## 3. 真实 P2-A 与目标差距

当前 DeviceSession 真成员里 InstanceContext 仍属于 Session；ResourceDomain 是 `SlotMap<unique_ptr<ResourceDomain>>` 和 Scene/View DomainIds；`Runtime/Objects.hpp` 中还有派生 `ExecutionJob`；RenderEffect 仍固定 `vulkan::EffectSource`，尚未有 effect-author Feature+logical Graph 组合或 ResourcePlan/attachment lease；Client/Server bootstrap 中立边界未彻底删除 Vulkan 专属参数；多 Effect Target、WSI/history、ECS/plugin Projection 与专业 Legacy Storage 均未完成。**不要在下一会话把本章提案中的 ScopeResources/ResourcePlan/Projection 当作已实现代码。**

## 4. 上一版 RD3-R2 的实际冲突及本版收敛

原 RD3-R2 把 InstanceContext 放在 DeviceSession、自有 ResourceDomain Tree 主导资源生死、Feature create 时预分配 Session/Effect GPU Resource、长期 ExecutionJob 缓存，同时没有 Engine-side Projection 的完整出口。RD3-R3 规定 Instance 外部 Native Bootstrap owned；Scope only sharing, Attachment RAII controls demand/use; ResourcePlan compile structural demands not discover from shader alone; Native resource acquisition at attach/preload; no independent writable ExecutionJob table; Engine DataProjection registered source and true R2 transport. DomainId 只做内部迁移适配，不是未来 must keep 公共 API。旧 TypeOwnership 66 行历史保留但明确 ARCHIVE，当前 TypeOwnership.csv 才是规范。

## 5. Legacy 需要继承而不是照搬的细节

`TGpuBuffer`: CPU_TO_GPU/GPU_ONLY policy, dirty epochs, optional host mirror, coalesced scratch; `PagedGpuStream`: page dirty-run batching; `StableRecordPages`: 4096 record stable pages; `MeshResources`: VMA TLSF chained arena VBO/IBO/LOD/Ready; `InstanceResources`: stable GPU slots/transform/cull/property streams/dense alive; `TextureResources/BindlessCombinedSet`: stable generation descriptor slot/mip residency/region updates; `MaterialResources/LightResources`: typed tables/SSBO/FIF revisions; `PointCloud`: chunk/octree/arrival ordered clear/upload/reset; `TransferScheduler/FifOwned`: staging ring batch and deferred GPU lifetime. 新 ScopeResources 只负责 Store、Lease、冷态查找；专业 Storage 的 update 仍强类型，不能统一成一个假 `upload(any)`。新的 Queue Ticket 替换不可靠 FrameSerial 作为物理退休依据。

## 6. UE-like H1–H6 非空泛需求

H1 Virtual Geometry GPU Page/Cluster/feedback/LOD/HZB；H2 Dynamic GI/Reflections with software SDF/Probe optional RT and temporal denoise；H3 temporal upscale motion/jitter/history/cut/reactive/disocclusion；H4 Virtual Shadow Atlas/Page cache/feedback/dirty/fallback；H5 advanced BSDF/Volume/Texture3D/multi-schema binding；H6 real GPU 3DGS chunk/tile bin/sort/splat/transmittance/mixed Mesh depth。Graph IR Native Executor 需有能力接缝；具体 Shader/Native primitives、质量/性能/设备 fallback 分阶段研发，不当作现已支持。Legacy PointCloud SoftSplat 不等于 Full 3DGS。
