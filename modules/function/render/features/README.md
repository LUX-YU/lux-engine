# Feature contracts and cold graph assembly

FeatureDescriptor contains stable type identity and optional full C++ configuration type/size/alignment qualification. It contains no callback, Command table, Shader or Native object. FeatureGraphOps supplies the synchronous describe/build algorithms; FeatureInstanceView borrows descriptor, graph operations, configuration owners and instance name for one assembly call. The registering module must remain loaded through every callback.

assembleFeatures validates identities and configurations, sorts full type/instance names, resolves claims, declares each shared resource once, invokes builders, finishes once, audits authorship and analyzes once. Command metadata is validated by the unique Runtime registration table, never by graph assembly. Results own one Definition, one Analysis, external GraphStorageBindings and contribution ranges; no input pointer escapes.

Only the provider may write a shared output. Initialized imported and previous-history ports use v0; graph-produced shared ports use v1. Private scratch uses ordinary G4 versions. The contribution's input_index/first_pass/pass_count is the authority for Program authorship. Zero-pass Features need no Program callback, but an explicitly provided parameter callback still contributes its values. Private pass/resource keys use featureKey's unambiguous type/instance/local encoding.

A selected Native FeatureProvider supplies graph contribution metadata and a concrete Handler type. The Server cold installation copies names/descriptor/graph callbacks into its stable FeatureId table and constructs or reuses the unique Handler by type and instance key. Command support comes from typed member bindings, with all recoverable qualification before publication. The former FeatureRegistration/CommandRegistration aggregates and null Native rebinding are removed. Graph-only providers use Handler=void; zero-pass Features require no dummy Program. ProgramContribution separates vector<PassProgram> from vector<StorageArgument>. Runtime resolves installed Storage qualifications and Program author names once. Native compilation receives immutable device facts, Definition/Analysis, GraphStorageBindings, the GraphPassId-indexed Program view and Target; Effect retains Attach arguments. Duplicate equal arguments are accepted; unequal values for one resource key fail cold. No mutable arguments enter CompiledGraph identity.

Scenarios A/B/C remain CPU authoring fixtures: Deferred/Lighting/Tonemap, static HZB Previous/Culling, and zero-pass Material Storage/Mesh. They do not claim production advanced rendering. Native tests independently cover the actual Offscreen, Texture and external Buffer path. Existing G5 reports remain historical and unchanged.

The component depends on Graph, Data, Commands and Resource; no Native, Runtime or IPC dependency. Feature configuration is an exclusive, move-only immutable ConfigValue. It counts only the data it owns; borrowed upload sources are not configuration owners. The defining module outlives construction, callbacks and destruction. CreateEffect selects server-local FeatureId values resolved from ListFeatures at a cold boundary. No Feature Wire codec or manual version remains; persistent encoding stays in the existing asset codecs. Configuration owners are retained by the caller during synchronous assembly or by the owning compile request during worker execution. No Feature callback runs in stable frames.
